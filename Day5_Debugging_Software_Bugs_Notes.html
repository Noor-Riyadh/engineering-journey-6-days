📝 محاضرة Day 5 — النوع الأول

Syntax Errors

❓ يعني إيه؟

مخالفة للقواعد الأساسية للغة البرمجة — زي نسيان نقطة أو قوس أو كلمة مكتوبة غلط.

🔍 مين بيكتشفه؟

💡 Tip: إضافة Error Lens في VS Code بتعلّم على الخطأ أثناء الكتابة مباشرة.

📝 محاضرة Day 5 — النوع الثاني

Runtime Errors

الكود مكتوب صح سينتاكس، بس الخطأ بيظهر وقت التشغيل والمشروع ممكن يقفل فجأة.

int a = 10;
int b = 0;
print(a / b); // IntegerDivisionByZeroException

✅ الحل: حماية الكود بـ try / catch عشان لو حصل Exception الأبلكيشن ما يقفلش.

try {
  print(a / b);
} catch (e) {
  print(e); // يطبع المشكلة والبرنامج يكمل عادي
}

📝 محاضرة Day 5 — النوع الرابع

Logical Errors

الكود شغال والـ Compiler ساكت، مفيش أي Crash، بس النتيجة النهائية غلط.

int age = 18;
if (age > 18) { // المفروض تكون >= 18
  print("Allowed");
} else {
  print("Not Allowed");
}
double total = 1000;
double discount = total * 0.05; // غلط! ده خصم 5% بس
// الصح: الضرب في 0.5 عشان يبقى الخصم 500

📝 محاضرة Day 5 — أنواع Software Bugs (1)

Functional · Crash · Security · Compatibility

⚙️ Functional Error

مشكلة وظيفية أثناء التنفيذ — مثال: تحويل غلط للحروف في الإيميل وقت الـ Login

💥 Crash Error

الأبلكيشن يقفل فجأة — مثال: قراءة Index مش موجود في قائمة عندها 5 عناصر بس

🔓 Security Error

ثغرة أمنية بتسرب أو تضرب بيانات

📱 Compatibility Error

الأبلكيشن مش شغال صح على كل الشاشات (Tablet, Mobile, Desktop)

📝 محاضرة Day 5 — أنواع Software Bugs (2)

Integration · Data · Requirements

🔗 Integration Error

كل جزء (Module/Service) شغال صح لوحده (Unit level)، لكن المشاكل بتظهر لما يتدمجوا مع بعض كسيستم واحد.

📊 Data Bug

الكود والمنطق سليمين 100%، لكن البيانات الممررة أو المخزنة هي المشكلة — فبتطلع نتائج غلط أو سلوك غير متوقع.

📋 Requirements Error — أخطر نوع!

بيحصل من مرحلة التخطيط قبل أي سطر كود — فهم غلط لطلبات العميل. النتيجة: كود سليم 100%، لكن المنتج مش اللي العميل عايزه.
